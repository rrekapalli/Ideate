# Product research

**Lens:** Analyst or Inventor on that workspace (dropdown), not a sixth v1 persona  
**Example named in the brief:** product research such as RxFolio-class work ([product-brief.md](../product-brief.md))

One person (a founder or a PM working alone) uses the same engine to keep **why the product is this shape** — user problems, bets, evidence from research, decisions, and killed ideas — instead of a graveyard of notes and chat threads. Shared product teams are a Pro workspace; this file is the single-person case.

## Job

Home asks the Analyst question (*why this decision?*) or the Inventor question (*what problem does this solve?*) depending on the workspace lens.

Success: a living graph of opportunities, assumptions, experiments (interviews, prototypes), and decisions they can replay months later.

## Lifecycle

```text
User / market problem → opportunity bets (hypotheses)
  → research evidence → critique → decision → shipped outcome
  → what we learned
```

Same loop as [consulting.md](./consulting.md) at the scale of one product and one author. No engagement roles, no client published view, no matter wall inside this workspace.

## Killer features

- Killed features remain objects (`abandoned` / `reused-in` when a later bet revives them).
- Interview notes attach to Evidence on a Hypothesis, not a folder of transcripts.
- “Why did we not build X?” is a provenance walk.

## Features — one person

| Feature | What it does |
| --- | --- |
| Problem pin | One Question: the user or market problem this workspace is about |
| Opportunity bets | Hypotheses (“job X is underserved”, “they will pay for Y”). Status visible without a team log |
| Assumptions | What must be true for the bet. “What breaks if this is false?” lists the decisions that depend on it |
| Research evidence | Interviews, usage notes, competitor pages, and pricing snapshots as Evidence on the bet. Tag `heard` on a quote and `concluded` only on an Evaluation or Decision |
| Do-not-quote | A sensitivity tag so a raw user quote is not pasted into an export |
| Experiment | A test intent (five interviews, a prototype, a landing page) and the Observation that came back |
| Critique | Structured doubt on a bet before it becomes a decision |
| Decision | Build, defer, or kill, with alternatives kept. Versions if the decision flips |
| Killed bets | `abandoned` with why, and `reused-in` if a later workspace revives the idea |
| Outcome | After shipping or after a test: what happened, written back on the Decision |
| Personal overlay | A rival product shape that does not overwrite the live bet |
| Decision replay | Months later: why not X, which interview weakened it, which constraint still holds |
| Solo brief | Export: problem, live bets, evidence, open assumptions, decisions, killed ideas |

Out of this file: squad comments, roadmap voting, stakeholder sign-off, a shared PM tool. Those wait on a team plan. The Analyst and Inventor lenses still supply the objects; this list does not add a Product persona.

## Objects emphasized

Question, Hypothesis, Assumption, Evidence (interviews, usage), Experiment, Decision, Constraint, Outcome. Design artifacts if the workspace is Inventor.
